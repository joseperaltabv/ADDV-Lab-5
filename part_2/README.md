## Part 2: Constrained-Random Instruction Generator

## Overview

Part 2 implements a constrained-random SystemVerilog instruction generator for the five-stage pipelined MIPS processor.

The generator creates valid MIPS instruction streams using the instruction subset required:

- ADD
- AND
- LW
- SW
- BEQ

The generated instruction sequence is converted into 32-bit MIPS machine code, written to a memory file using $writememh, loaded into the processor instruction memory using $readmemh, and then executed by the pipelined MIPS processor.

## Constraints

The implementation requires these stimulus limits:

- Randomized registers: $1, $2, $3, $4
- Data memory addresses:
  - 0x00000000
  - 0x00000004
  - 0x00000008
  - 0x0000000C
- Dependency gaps: 1, 2, 3, and 4 instructions
- BEQ offsets: 1, 2, 3, and 4

Register $0 is used only as a fixed base register for LW and SW instructions so that the immediate field directly represents the required memory address. It is not part of the randomized register set.

## File Descriptions

### controller_lab5.sv

Contains the control logic for the pipelined MIPS processor.

### datapath_lab5.sv

Contains the five-stage pipelined MIPS datapath.

### top_lab5.sv

Contains the top-level processor module, instruction memory, and data memory.

### instr_gen_lab5.sv

Contains the constrained-random instruction generator.

It implements:

- An instruction class extending uvm_transaction
- Randomizable instruction fields
- Constraints for ADD, AND, LW, SW, and BEQ
- Register constraints
- Memory-address constraints
- Dependency-gap constraints
- Branch-offset constraints
- Taken and not-taken BEQ scenarios
- Register-dependent instruction pairs
- Memory-dependent SW/LW instruction pairs
- Dynamic instruction arrays
- MIPS machine-code encoding
- $writememh generation of the instruction program

### testbench_lab5.sv

Contains the Part 2 testbench.

It performs:

- DUT instantiation
- Clock and reset generation
- Data-memory initialization
- Construction and execution of the instruction generator
- Loading the generated program into dut.imem.RAM using $readmemh
- Instruction-fetch monitoring
- FSDB waveform generation
- End-of-simulation trickbox detection

### generated_program.mem

Contains an example machine-code instruction stream produced by the constrained-random instruction generator.

### memfile.dat

Placeholder instruction-memory initialization file required by the original Lab 2 instruction-memory module.

The generated program is later loaded into instruction memory before reset is deasserted.

### Makefile

Provides commands for compiling the processor and testbench using Synopsys VCS, running the simulation with a selectable random seed, and opening the generated waveform in Verdi.

## Compile

make clean
make comp

## Run

A simulation can be run using:

make run SEED=244

Different random instruction streams can be generated by changing the seed.

## Successful Simulation

The generated program ends using an end-of-simulation trickbox.

The final instruction sequence stores:

Address = 0x0000000C
Data    = 0xDEADBEEF

The testbench detects this event and terminates the simulation.

A successful simulation reports:

END-OF-SIMULATION TRICKBOX DETECTED
Address = 0x0000000c
Data    = 0xdeadbeef
Simulation completed successfully.
